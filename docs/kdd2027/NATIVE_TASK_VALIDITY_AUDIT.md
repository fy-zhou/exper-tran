# Validity audit: why native-task targeted ASR is low

These are exploratory adapted results. They are not official COCO/LLaVA targeted-attack scores, and the cross-task implementation has not established equivalence to the original ImageNet method. Strong quality degradation does not establish controlled targeted transfer. Do not claim that every low targeted score is a judge artifact or that it proves the original algorithm fails.

## Verified observations and protocol differences

1. **Genuine target misses exist.** In an Ours adversarial COCO response (source ID422836, InternVL14B), the frozen target descriptions depict people beside a bus/jetliner, whereas the answer describes a crane in front of a building. The response does not express the intended target. This is a negative illustrative example, not an estimate of the failure-category frequency.
2. **Goal granularity can change the interpretation.** For LLaVA source408439/Qwen27B, the target describes a man leading a cow. The adversarial answer introduces a cow but describes a woman and cow in water. The current scene-consistency judge rejects it. A predeclared entity-level goal and a full-scene relational goal are different tasks; the target entity appearing does not justify silently rewriting the current labels. This exposes an unresolved alignment between the paper's semantic target and the adapted whole-image criterion.
3. **The reference construction changed.** Original ImageNet uses48 human-class-consistent references. The native-task extension uses48 CLIP-nearest unlabeled COCO references from a512-image pool. Both use the same .5/.5 loss/update, but this is a material methodological adaptation. Prototype dilution or mixed scene semantics is a hypothesis, not a quantitatively established cause.
4. **Targets were not chosen for question compatibility.** The existing seed42 manifest pairs LLaVA images with unrelated COCO target images. For example, a question about planes' effect on birds is paired with a water-skier target. Requiring an answer to retain that question, ground itself in a different scene, and affirm target-specific content can make the intended target answer poorly defined. The size of this effect has not been measured.
5. **Judgment reliability remains unverified.** The strict source/target semantic predicate is post-hoc and implemented with fixed open-weight judges, without a completed human-agreement study. Raw judgments and original pairings are retained. No score threshold, new target or looser rule may be selected from these final outputs to manufacture a higher headline score.

Failure observations above were taken only from `adv` request IDs belonging to Ours, rather than from the mixture of clean/adversarial judgments. Source/target IDs, raw answers and judge rationales are available in `results/native_task_targeted_asr_v1/case_provenance.json` and the persistent raw-judgment archive. Illustrative cases do not constitute a human validation set.

## What the official benchmarks evaluate

- **COCO captioning:** compare generated descriptions with human references using BLEU, METEOR, ROUGE-L, CIDEr and SPICE. The official evaluation implementation does not define our target-image semantic attack ASR. Our150-image subset/IDF population and224px canvas are explicit adaptations, not official full-benchmark numbers. [COCO caption evaluation code](https://github.com/tylin/coco-caption).
- **LLaVA-Bench(COCO):**30 COCO-Val2014 images and90 conversation/detail/reasoning questions. The original method uses GPT4 to rate answer quality on a1–10 scale and reports relative scores against its reference answers. It is not a target-image attack-success benchmark. The In-the-Wild24-image/60-question variant is a different set and must not be conflated with COCO. [Original paper, Section5.1](https://arxiv.org/html/2304.08485v2), [upstream evaluator](https://github.com/haotian-liu/LLaVA/blob/c121f0432da27facab705978f83c4ada465e46fd/llava/eval/eval_gpt_review_bench.py).

## Required before a final cross-task targeted-transfer claim

Freeze the intended target granularity (entity/attribute/whole scene/answer) with question-compatible targets before a new held-out run; validate reference-bank semantics and a blinded human sample of judge labels. Keep native quality results and targeted success as separate measurements. Use independent development data for protocol/method choices; report all current attempts as exploratory, rather than retroactively relabeling observed outputs under whichever goal scores highest. Existing baseline/raw-output generation can still be reused as reproducible exploratory evidence; it does not resolve these validity questions by itself.

## Recorded proxy optimization signal

The540 full-run Ours attack receipts were checked against their saved50-step loss traces (pilot-reused receipts resolve back to the original trace). In534/540 cases, the arithmetic mean of per-proxy losses is lower at the last recorded step than at the first. Mean start/end values are approximately1.01–1.03 and0.97–0.98. The actual DI views differ between steps; this is a descriptive training-view signal, **not** a convergence test or evidence that the final victim output matches the target.

For the balanced objective, L=1+0.5(cos_source−cos_target). A lower value can arise from decreasing source similarity without a sufficient increase in absolute target similarity; it does not enforce dominance over every alternative semantic interpretation or the victim language output. These traces do not separately store absolute Pull/Push components, so attributing the observed loss change to source repulsion versus target attraction requires further measurement. See `results/native_tasks_ours_first/optimization_trace_audit.json` for per-condition statistics and all trace hashes. No attack/model configuration or output was changed by this CPU-only audit.
